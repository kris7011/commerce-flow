# CommerceFlow v1.0.0 — Reliable Event-Driven Commerce

The first portfolio release of **CommerceFlow**, an event-driven commerce backend demonstrating how TypeScript microservices coordinate through RabbitMQ and maintain consistent inventory in PostgreSQL.

## What's included

- **Five services:** Order, Payment (simulated), Inventory, Delivery (simulated) and Notification.
- **Transactional outbox:** Inventory reservations, business-key idempotency records and outgoing events are committed atomically in PostgreSQL.
- **Reliable RabbitMQ routing:** Mandatory publications, publisher confirms and correlated returned-message handling. All consumer queue bindings are provisioned before messages are published.
- **Recovery and concurrency:** Leased outbox dispatch, retry with backoff, poison-message dead-lettering, reconnecting consumers, multiple relays and graceful shutdown.
- **Type-safe architecture:** Shared event contracts with runtime validation, clear service boundaries and small infrastructure adapters.
- **Automated verification:** CI on Node.js 22 and 24 runs audit, lint, typecheck, build, unit tests, PostgreSQL and RabbitMQ integration tests, and end-to-end/recovery tests against real infrastructure.

## Run locally

Requires **Node.js 22 or 24** and **Docker Compose**.

```bash
npm ci
docker compose up -d --wait rabbitmq postgres
```

Start the five services in separate terminals with `npm run dev:notification`, `npm run dev:delivery`, `npm run dev:inventory`, `npm run dev:payment` and `npm run dev:order`. The public API accepts orders at `POST http://localhost:3001/orders`.

To run the complete checks:

```bash
npm run lint
npm run typecheck
npm run build
npm test
npm run test:integration
npm run test:e2e
```

Integration and E2E tests require the Docker services.

## Scope and limitations

This is a **portfolio and educational release**, not production software. It deliberately uses simulated payments and delivery, in-memory notifications, and no persistent order-level idempotency key. Message delivery is **at-least-once**, not exactly-once. See the [known limitations](https://github.com/kris7011/commerce-flow#known-limitations) for details.
